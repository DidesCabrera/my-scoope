# AI Capability Portfolio Report

Use this format when Felipe asks for an overview of the AI team, its roles,
capabilities, or development. The report is intended for conversation: keep it
compact, explain material evidence, and expand only the rows that need a decision.

## Distinguish lifecycle from maturity

Report the registry lifecycle state exactly as recorded. Assess operational
maturity separately:

- **M0 — Need:** the recurring outcome is identified, but no usable capability
  exists.
- **M1 — Defined:** instructions, authority boundaries, and expected deliverable
  exist.
- **M2 — Usable:** the capability can perform a realistic task, but evidence is
  limited or configuration remains incomplete.
- **M3 — Proven:** repeated use demonstrates stable routing, useful results, and
  reliable boundaries.
- **M4 — Improving:** performance is measured and the capability is deliberately
  refined from accumulated evidence.

Maturity is an evidence-based assessment, not another registry field. Do not infer
it only from file completeness or lifecycle status. State `unassessed` when the
available evidence is insufficient.

## Default chat report

### AI team snapshot

Include the report date, registry review date, counts of roles and shared skills,
and the lifecycle distribution. Lead with material inconsistencies or blockers.

### Roles

Use one row per role:

| Role | Area / class | Core capability | Lifecycle | Maturity | Evidence | Main gap | Next evaluation |
|---|---|---|---|---|---|---|---|

Keep capabilities outcome-oriented. Evidence must refer to observed use, a
validated workflow, or a durable artifact. A skill file by itself proves M1 only.

### Shared workflow skills

Use one row per shared skill:

| Shared skill | Typical users | Repeatable outcome | Lifecycle | Maturity | Evidence / gap | Next evaluation |
|---|---|---|---|---|---|---|

Shared skills do not appear in the organigram and do not grant authority.

### Decisions and attention

End with no more than three groups:

- **Decisions needed:** choices that require Felipe's authority.
- **Priority improvements:** smallest changes that improve reliability or remove a
  material capability gap.
- **Watch list:** pilots, provisional capabilities, overlaps, or missing evidence
  that should be observed before changing the portfolio.

For each item, name the evidence and the next concrete conversation or task that
would resolve it. Do not recommend creating roles merely to make the organization
symmetrical.

## Report depth

- **Compact:** snapshot, material exceptions, and decisions only.
- **Standard:** full role and shared-skill tables plus decisions and attention.
- **Focused:** only one area or one capability, with deeper evidence and next-test
  detail.

Use the standard report when Felipe does not specify a depth.
