# 0117 — AI Assistant post-tool local acknowledgements are state-only

## Status

Accepted and implemented during CM24 UX closure.

## Context

The eighth CM24 live report passed every automated runtime invariant. Human transcript review still found one repetitive pattern in `cambio_de_direccion`:

```text
Para seguir, cuéntame si quieres usar tu ficha personal como base o prefieres entregar datos nuevos para este plan.
```

The phrase appeared after three consecutive proposal updates, including after the user explicitly said to continue without more preferences.

This wording was not generated by the normal provider response. Each native function call succeeded, but the provider failed only on the post-tool wording request. My Scoope then used its local technical acknowledgement. That fallback summarized the tool result and also selected a next question based on missing profile data.

The second behavior violated the boundary established in CM23. A local transport fallback is allowed to communicate validated state, but it must not become a second conversational planner.

## Decision

Post-tool local acknowledgements are **state-only**.

They may:

- summarize successful typed tool results;
- report a typed read error such as `not_found`;
- clarify that no persistent change was applied;
- preserve native function-call and degradation metadata.

They must not:

- choose the next question;
- infer a missing-field agenda;
- ask whether to use the personal profile or new data;
- repeat a generic closing prompt;
- parse the user message to invent additional state;
- invoke deterministic intake.

For proposal updates, the local acknowledgement uses the validated proposal draft itself. For example:

```text
Perfecto. La propuesta queda como un programa semanal para bajar grasa, con 3 comidas al día.
```

The next user turn returns control to the LLM, which can decide naturally whether a clarification or tool call is useful.

## Automated protection

The CM24 report records:

```text
tool_followup_local_ack
tool_followup_local_ack_policy = state_ack_only.v1
provider_tool_followup_failed
```

The `post_tool_fallback_pacing` invariant rejects a local post-tool acknowledgement that:

- uses a different policy;
- contains a question;
- appends known interviewer phrases such as `Para seguir` or `prefieres entregar datos nuevos`.

This invariant applies only to the local technical fallback. It does not limit questions generated by the normal LLM response.

## Consequences

- Provider failures after successful tools no longer create a robotic intake loop.
- The backend does not own the next conversational step in LLM mode.
- User instructions such as “avancemos” are not contradicted by a fallback-generated question.
- Technical resilience remains available without hiding validated tool results.
- A targeted live rerun of `cambio_de_direccion` is required before final CM24 closure.
